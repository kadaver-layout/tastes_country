# QA-аудит v3 — Products и расписание

Дата: 27.11.2026. Версия проверена после повторных исправлений. Это **новый аудит**, а не подтверждение закрытия предыдущих замечаний.

## Как проверялось

- Собрана production-версия: `npx gulp build --prod` — успешно.
- Запущен `npm run qa:v2`: 84 сочетания страниц/ширин, ресурсы, формы, reduced motion, рельсы, FAQ и переключение недель — `PASS`.
- Выполнено наложение (overlay) актуальных экранов и экспорта Figma для 375 / 768 / 1280 / 1920. Файлы: `.figma/build-shots/qa2-overlays/products-*.png`, `.figma/build-shots/qa2-overlays/schedule-*.png`.

**Не принимать как pixel-perfect.** Базовые размеры большинства крупных секций стали значительно ближе к Figma, а вертикальное колесо больше не переключает transform-слайдеры. Но есть блокирующие визуальные расхождения на mobile и существенные недочёты контракта/UX календаря.

## P0 — Products: исправить перед следующей приёмкой

### P0-PR-01. На 375 px поверх каталога висит лишняя кнопка «Перейти к выбору категории»

**Где:** `products.html`, ширина 375 px; `.back-to-categories`.

**Факт:** кнопка с `position: fixed` выводится поверх заголовка «С чего начнём?» и первой зоны списка. Это видно на актуальном скриншоте `products-375.png`: зелёная кнопка перекрывает вводный текст и карточки. В Figma 375 (`1:2425`) такой кнопки нет.

**Причина:** в `src/assets/styles/main.sass` у `.back-to-categories` безусловно задано `position: fixed`; mobile-правило меняет только `right`/`bottom`.

**ТЗ для QWEN:**

1. До mobile-бекпойнта включительно скрыть кнопку: `display: none` именно у `.main--products .back-to-categories`. Не оставлять прозрачную кнопку и не резервировать под неё место.
2. На 768 и 1280 вернуть вариант Figma размером 284×59 px; на 1920 — 337×76 px. Если это fixed-элемент, он не должен перекрывать заголовки, карточки, CTA и footer при скролле.
3. Не менять DOM-порядок секций ради этого исправления.
4. Проверить клавиатурой: скрытая mobile-кнопка не должна попадать в Tab-порядок.

**Критерий приёмки:** в full-page screenshot 375 кнопки нет; на 768/1280/1920 она соответствует Figma, кликабельна и ведёт на `#categories`.

### P0-SC-02. Перепутаны стартовые изображения галереи и discount-блока

**Где:** Schedule 375; `.gallery`, `.discount`.

**Факт:** Figma показывает первым в галерее продавца с продуктом и в discount — сырную композицию. В текущей сборке первым показываются другие изображения (чайный процесс в галерее и чайная композиция в discount). Overlay фиксирует двойные, не совпадающие изображения.

**Причина:** глобальные данные `gallery.photos` используются несколькими страницами, а их текущий порядок начинается с `hero-12`. Один общий порядок нельзя считать источником для разных экранов, если в Figma у них разные стартовые кадры.

**ТЗ для QWEN:**

1. Создать отдельные page-level данные, например `schedule.gallerySlides` и `schedule.discountImage`; не менять наугад общий `gallery.photos`.
2. Сопоставить каждый файл с экспортом Figma до правки: первый видимый кадр Schedule 375/768/1280/1920 обязан быть одинаковым с макетом до первого клика.
3. Для каждого слайда хранить `id`, `image`, `alt`, `desktopCrop`, `tabletCrop`, `mobileCrop` при необходимости. Не использовать CSS `object-position` как скрытую замену неправильному ассету.
4. Добавить проверку: initial slide = Figma first slide; после Next — второй уникальный слайд; после Prev возвращается первый.

## Календарь: что уже работает и что надо переделать

### Проверено сейчас

- На 768 текущий fallback переключает недели: 19–25 октября → 26 октября – 1 ноября → 2–8 ноября; кнопки корректно disabled на первом/последнем локальном массиве.
- Интервал ярмарки корректно визуально обрезается границей недели. Например событие 19.10–07.11 занимает все дни первой недели; на 02–08.11 занимает только 02–07.11.
- Синтетическое вертикальное колесо над native-rail и transform-rail не меняет `scrollLeft`/`transform`; прокручивается страница. Регресс «слайдер листается при вертикальном скролле» в актуальной сборке не воспроизведён.

### P0-CAL-01. Нынешний контракт `loadWeek(direction)` непригоден для живого расписания

**Факт:** фронтенд сперва читает статический `#schedule-weeks`, а затем допускает переход только внутри `weeks.length`. Даже при наличии `window.TastesIntegrations.loadWeek` нельзя запросить четвёртую неделю: расчёт `target` останавливается раньше. В интеграцию передаётся только `-1`/`+1`, а не дата нужной недели.

**ТЗ для QWEN:**

1. Заменить интеграционный метод на `loadScheduleWeek({ weekStart, cityId, signal })`, где `weekStart` — понедельник в ISO `YYYY-MM-DD`.
2. Следующую/предыдущую дату вычислять фронтендом календарно (`±7` дней), а доступность брать из ответа API: `hasPrev`, `hasNext`. Не ограничивать по размеру preloaded массива.
3. На каждый переход создать `AbortController`; отменять прежний запрос, блокировать обе стрелки только на время текущего запроса, игнорировать устаревший ответ.
4. Синхронизировать состояние с URL, например `?week=2026-10-19&city=moscow`, через `history.pushState`; поддержать Back/Forward.
5. Статический JSON оставить лишь как development fallback и явно пометить его так. В production не дублировать все недели в DOM.

### P0-CAL-02. Календарь пока не кликабелен как календарь

**Факт:** заголовки дней отрисовываются как `<li>`, полосы ярмарок — как `<p>`. Кликнуть день для фильтрации нельзя, открыть площадку из строки нельзя. Доступны только две стрелки недели.

**ТЗ для QWEN:**

1. Каждый день отрисовывать кнопкой: `<button type="button" data-date="YYYY-MM-DD">`. У кнопки — понятный `aria-label` («22 октября, сегодня»), у выбранной даты `aria-pressed="true"`.
2. Сохранить Figma-состояние «сегодня» (оранжевая плашка) отдельно от выбранного дня. Для выбранного, но не сегодняшнего дня применить outline/не меняющий размеры стиль, согласованный с дизайнером; DOM и размеры сетки не должны прыгать.
3. По клику дня фильтровать/подсвечивать только события, пересекающие эту дату. Если их нет — выводить доступный empty state («На эту дату ярмарок нет»), а не пустую таблицу без пояснения.
4. Полоса события должна быть ссылкой на страницу/модальное окно конкретной площадки либо кнопкой с таким действием. `p.schedule__bar` заменить на интерактивный элемент; маршрут в карточке и в календаре должен вести в одно и то же место.
5. Обеспечить keyboard flow: Tab → дни → события → Prev/Next; Enter/Space активируют элементы; `aria-live` сообщает новую неделю и число найденных площадок.
6. На 375 календарь по Figma скрыт — это допустимо. Но mobile-карточки должны быть ссылками на те же `eventId`, а не второй вручную поддерживаемой копией расписания.

### P1-CAL-03. `today` сейчас зашит исторической датой

В JSON присутствует `"today": "2026-10-22"`. После этой даты интерфейс будет выделять устаревший день. API должен возвращать `today` только как серверную дату в `Europe/Moscow` либо фронтенд должен вычислять её из серверного `now`; если открыта не текущая неделя, ни один день не выделяется как today.

## Точный формат данных для бэкенда расписания

### Не заполнять недели вручную

Не создавать на бэкенде отдельные копии одной и той же ярмарки в `weeks[0]`, `weeks[1]`, `weeks[2]`. Оператор заносит **одно событие-площадку с полным интервалом**. Сервер сам выбирает события, пересекающие требуемую неделю:

```text
starts_on <= week_end AND ends_on >= week_start
```

Это обязательно: ярмарка, которая началась раньше понедельника или закончится после воскресенья, всё равно должна попасть в таблицу.

### Что заполняет контент-менеджер для одной площадки

| Поле | Тип / пример | Правило |
|---|---|---|
| `id` | `fair-msk-butovo-2026-10-19` | Не меняется при редактировании текста. |
| `city.id`, `city.name` | `moscow`, `г. Москва` | Город из справочника, не свободная строка. |
| `venue.id` | `butovo-mall` | Стабильный id площадки. |
| `venue.name`, `venue.address` | `ТЦ «Бутово Молл»`, `Чечерский проезд, 51` | Полное отображаемое название/адрес. |
| `starts_on`, `ends_on` | `2026-10-19`, `2026-11-07` | ISO-даты, включительно, без `19–7` и без локального текста. |
| `opens_at`, `closes_at` | `09:00`, `21:00` | Необязательно; для карточки/деталей. |
| `timezone` | `Europe/Moscow` | Обязательно для расчёта today и часов. |
| `status` | `published` / `cancelled` / `draft` | `draft` и `cancelled` не попадают в публичный ответ. |
| `route_url`, `detail_url` | URL | Валидные https/относительные ссылки; используются всеми представлениями. |
| `sort` | `100` | Явный порядок при одинаковых датах. |

Сервер валидирует `starts_on <= ends_on`, реальность ISO-даты, допустимую timezone и уникальность `id`. Изменение года/интервала — не повод подменять id другого события.

### Ответ API, который нужен фронтенду

```json
{
  "week_start": "2026-10-19",
  "week_end": "2026-10-25",
  "timezone": "Europe/Moscow",
  "today": "2026-10-22",
  "has_prev": true,
  "has_next": true,
  "rows": [
    {
      "id": "fair-msk-butovo-2026-10-19",
      "city": { "id": "moscow", "name": "г. Москва" },
      "venue": {
        "id": "butovo-mall",
        "name": "ТЦ «Бутово Молл»",
        "address": "Чечерский проезд, 51"
      },
      "starts_on": "2026-10-19",
      "ends_on": "2026-11-07",
      "opens_at": "09:00",
      "closes_at": "21:00",
      "status": "published",
      "detail_url": "/schedule/fair-msk-butovo-2026-10-19/",
      "route_url": "https://maps.example/...",
      "sort": 100
    }
  ]
}
```

**Рендер-правило:** подпись бара показывает настоящий полный интервал, а его геометрия строится по пересечению с `week_start…week_end`. Например, 19.10–07.11 на неделе 02–08.11 рисуется с 02 по 07, но подписывается полным сроком либо доступным tooltip/деталями.

**Сортировка:** `city.sort`, затем `venue.sort`, затем `starts_on`, затем `id`. Если один и тот же venue имеет пересекающиеся события, API обязан вернуть `lane` (0, 1, …), чтобы бары не накладывались; фронтенд не должен угадывать порядок.

**Единый источник:** featured-карточки 375, таблица 768+ и детали ярмарки берут данные одного `eventId`. Нельзя отдельно вести «две карточки для mobile» и «строки календаря».

## Регрессия слайдеров и анимаций

Текущая transform-реализация для `data-rail-mode="slide"` не подписывается на `wheel`; вертикальный wheel над проверенными rail на 375/768 сдвигал страницу, но не слайд. Это исправление **сохранять**.

Перед сдачей QWEN должен повторить:

1. Wheel вверх/вниз над каждой каруселью: `scrollLeft` и `transform` не меняются.
2. Стрелки меняют ровно один слайд; быстрое 5× нажатие не создаёт двойных клонов/скачков.
3. `prefers-reduced-motion: reduce`: без анимации, логика/позиция одинаковы.
4. Touch: горизонтальный свайп допустим только для native-rail, вертикальный жест не захватывается каруселью.
5. Первый видимый слайд каждого блока совпадает с Figma ещё до любого взаимодействия.
